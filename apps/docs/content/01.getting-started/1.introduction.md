`@chronicstone/vue-route-query` binds query-string keys to writable refs. The value is parsed into a real type, written back to the URL when you assign it, and kept in step with the back and forward buttons.

Type in the box below, then reload the page or copy the link into another tab.

::demo-hello
::

```ts twoslash
import { stringCodec, useQueryState } from '@chronicstone/vue-route-query'
// ---cut---
const name = useQueryState('name', stringCodec({ default: '' }))
//    ^?
```

```vue
<template>
  <UInput v-model="name" placeholder="Your name" />
  <p>Hello, {{ name || 'anonymous visitor' }}!</p>
</template>
```

## Why put state in the URL

Filters, tabs, sort orders, the page of a table, an open side panel: if a user would want it to survive a reload, or to send it to a colleague, it belongs in the URL. Keeping it there by hand means reading `route.query` strings, parsing them, writing them back with `router.replace`, and making sure two components writing at once do not overwrite each other.

This library does that part:

- **Typed and checked.** A [codec](/codecs/built-in-codecs) turns the raw string into a `number`, `Date`, a string union, an array, or your own type, and checks it: `min`, `max`, `int`, lengths, patterns. A value that breaks a rule falls back to the default.
- **Batched.** Every write made in the same tick becomes [one navigation](/guide/batching), across all components.
- **Grouped.** Bind several keys to one object with [`useQueryStates`](/guide/grouped-values), under an optional prefix.
- **Cross-field rules.** Declare that `from` comes before `to`, and a link that breaks it loses only the key you name. See [Validation](/guide/validation).
- **Dynamic.** Keys that only exist at runtime, such as user-defined filters, are supported with [`dynamicQueryState`](/guide/dynamic-keys).
- **Small.** About 7 kB gzipped, with `vue` and `vue-router` as its only peer dependencies. No validation library is bundled.
